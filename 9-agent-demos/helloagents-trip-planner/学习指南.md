## 一、这一章和前几章的读法完全不同

前几章的目录是**一组按节编号的教学脚本**（`01_xxx.py`、`02_xxx.py`…），跑一个学一个。
这一章只有一个**完整的前后端分离应用**，目录里没有编号、没有"逐文件跑"这回事：

| 层 | 技术 | 真正要读的量 |
|---|---|---|
| 后端 | FastAPI + HelloAgents | **`agents/trip_planner_agent.py` 435 行是整章的"智能体本体"** |
| 前端 | Vue 3 + TS + Vite + Ant Design Vue | `views/Result.vue`(1399) / `views/Home.vue`(654) |
| 其余 | 配置 / 路由 / 服务 / 类型 | Web 脚手架，扫一眼即可 |

**所以正确读法是「沿一条请求链路自顶向下读」，而不是「逐文件跑」**：

```
浏览器填表 → POST /api/trip/plan → 4 个 Agent 依次协作（3 个调 MCP 拿真实数据，1 个纯 LLM 汇总）
          → 返回 TripPlan → 前端存 sessionStorage → Result 页渲染（地图 + 配图 + 编辑 + 导出）
```

把这条链路走通，本章 90% 的知识点就拿到了；剩下的是 Web 工程细节（表单、进度条、导出）。

## 二、跑起来（本机已全部验证，照抄即可）

### 2.1 后端

**⚠️ 入口是 `backend/run.py`，不是 `app/api/main.py`。**

`main.py` 第 5 行用了相对导入 `from ..config import ...`。相对导入只在"作为包的子模块被加载"时有效；
在 PyCharm 里右键 `main.py` → Run/Debug 是把它当**独立脚本**执行，Python 不知道父包是谁，必报：

```
ImportError: attempted relative import with no known parent package
```

`run.py` 走的是 `uvicorn.run("app.api.main:app", ...)`，以包路径加载，才是正确入口。

PyCharm 运行配置（一次性）：

| 项 | 值 |
|---|---|
| Script path | `...\helloagents-trip-planner\backend\run.py` |
| Python interpreter | 项目根 `.venv\Scripts\python.exe` |
| **Working directory** | `...\helloagents-trip-planner\backend` ← 最关键，`load_dotenv()` 靠它找 `backend/.env` |

命令行等价写法：

```bash
cd <项目根>/9-agent-demos/helloagents-trip-planner/backend
<项目根>/.venv/Scripts/python.exe run.py      # 起在 http://localhost:8000
# 探活：curl http://127.0.0.1:8000/docs  → 200
```

### 2.2 前端

```bash
cd <项目根>/9-agent-demos/helloagents-trip-planner/frontend
npm install          # 首次必须；node_modules 不入库
npm run dev          # 默认 5173；被占用会自动 +1 → 5174 ...
```

PyCharm 里可建 **npm** 类型运行配置：package.json 选 `frontend/package.json`，Command=`run`，Scripts=`dev`。

**启动顺序：先后端，后前端。** 前端结果页 `loadAttractionPhotos()` 里硬编码了 `http://localhost:8000`，
后端没起来时页面能打开，但规划请求和配图都会失败。

## 四、核心链路拆解（一次「生成旅行计划」到底发生了什么）

`trip_planner_agent.py` 的 `MultiAgentTripPlanner.plan_trip()` 是四个 Agent **顺序**协作，不是并行：

```
前端 Home.vue handleSubmit()
  └─ POST /api/trip/plan                        routes/trip.py
       └─ get_trip_planner_agent()              单例；首次调用时构造 1 个 MCPTool + 4 个 SimpleAgent
            ├─ 步骤1 景点Agent.run(query)
            │    提示词强制 LLM 输出：[TOOL_CALL:amap_maps_text_search:keywords=历史文化,city=北京]
            │    → 框架解析 → 调高德 MCP → 返回真实 POI
            ├─ 步骤2 天气Agent.run(query)      → [TOOL_CALL:amap_maps_weather:city=北京]
            ├─ 步骤3 酒店Agent.run(query)      → [TOOL_CALL:amap_maps_text_search:keywords=酒店,city=北京]
            └─ 步骤4 规划Agent.run(query)      ← 这个 Agent **没有工具**，纯 LLM
                 _build_planner_query() 把上面三段的**真实返回文本**整段拼进 prompt
                 → LLM 输出一大段 JSON（```json ... ```）
       └─ _parse_response()   抠 ```json 代码块 → json.loads → TripPlan(**data)
            └─ 失败 → _create_fallback_plan()（编造数据！见坑 12）
  └─ 前端 sessionStorage.setItem('tripPlan', ...) → router.push('/result')
       └─ Result.vue onMounted → loadAttractionPhotos() + initMap()
```

### 4.1 关键：MCP 工具名「两套」，各用一处（易混，实测确证）

| 调用方式 | 该用的名字 | 机制 |
|---|---|---|
| 代码里直接 `MCPTool.run({...})`（如 `amap_service.search_poi`） | **`maps_text_search`**（无前缀） | `run()` 原样透传给 MCP 服务端 |
| Agent 经 `[TOOL_CALL:...]` 调用（4 个提示词里写的） | **`amap_maps_text_search`**（带前缀） | `MCPWrappedTool.run()` 内部 `tool_name: self.mcp_tool_name` 自动剥前缀 |

- 机制：`ToolRegistry.register_tool()` 在 `expandable=True` 时，把服务端 16 个 `maps_*` 工具**注册成带 `{tool.name}_` 前缀的名字**（本例 `amap_`）。
- `SimpleAgent._parse_tool_calls()` 用正则 `\[TOOL_CALL:([^:]+):([^\]]+)\]` 取名 → 查注册表 → 命中。
- **上游提示词里的 `amap_maps_text_search` 是对的，不要改。** 只设 `auto_expand=True` 而不设 `expandable=True` 不会展开
  （注册表里只剩 `amap` 一个），项目代码两个都设了，所以正常。
- 实测：16 个工具全部注册为 `amap_maps_*`；M3 确实成功输出了 `[TOOL_CALL:amap_maps_text_search:...]` 并执行成功。

### 4.2 为什么用 MCP 而不是直接调高德 REST（教材 13.4.1）

`MCPTool(name="amap", server_command=[...], env={"AMAP_MAPS_API_KEY": key}, auto_expand=True, expandable=True)`
一行就把 `amap-mcp-server` 的 16 个工具（POI 搜索、天气、驾车/步行/公交路径、地理编码、周边搜索…）
变成 Agent 可调用的工具集，**不需要为每个接口写适配代码**。全章只创建 **1 个** MCPTool 实例、被 3 个 Agent 共享（13.4.3）。

## 六、已知坑清单（实测踩过的，排错先查这里）

### 坑 1 · 右键 `main.py` 报 `attempted relative import with no known parent package`
见 2.1。**入口只能是 `run.py`**，或 `uvicorn app.api.main:app`（cwd=backend）。

### 坑 2 · `uvx amap-mcp-server` 起来后**静默 0 个工具**（最阴的一条）
- `amap-mcp-server 0.1.11` 锁死 `mcp==1.8.1`，而该版本需要 `pydantic<2.9` 才有的 `eval_type_backport`；
  uvx 默认装最新 pydantic（2.12）→ **MCP 子进程 ImportError 崩溃** →
  `MCPTool` 的 `get_expanded_tools()` **静默返回 0 个工具、不抛异常**，启动日志一切正常，只是永远调不到地图。
- **修法**：`server_command=["uvx", "--with", "pydantic<2.9", "amap-mcp-server"]`。
  已改 `trip_planner_agent.py:176` 与 `amap_service.py:34` 两处。修复后实测 16 个工具全注册。

### 坑 3 · `LLM_TIMEOUT=60` 不够 → 静默 fallback
- 实测最终"行程规划"那一步**单次就要 33 秒、输出 10887 字符**；而 `_build_planner_query()` 把
  景点+天气+酒店三大段真实数据**全拼进 prompt**，输入更长 → 60 秒必然 `Request timed out`
  → 走 `_create_fallback_plan()`（数据是假的）。
- **修法**：`backend/.env` 把 `LLM_TIMEOUT` 提到 **300**。

### 坑 4 · 前端端口漂移 5174/5175 → CORS 400
- Vite 在 5173 被占用时会自动 +1 换端口，而 `CORS_ORIGINS` 只配了 5173/3000
  → 浏览器 **OPTIONS 预检**被 FastAPI 中间件拒绝：`400 Disallowed CORS origin`（真正的 POST 根本发不出）。
- **修法**：`CORS_ORIGINS` 覆盖 5173–5176 + 3000（localhost 与 127.0.0.1 两种写法）。
- ⚠️ **改 `.env` 后必须重启后端**：`reload=True` 只盯 `.py`，配置是模块导入时一次性读入的。
- 另一种更省心的做法：`vite.config.ts` 里 `server: { port: 5173, strictPort: true }`，被占就报错而不是悄悄换号。

### 坑 5 · 高德 Key 返回 `10001 INVALID_USER_KEY` —— 先怀疑"Key 抄错了"
- **血泪教训**：从截图里肉眼读 Key，曾把 `...b569cd37` 读成 `...b569dc37`（`cd`↔`dc` 看反）。
  一个**不存在的 Key** 返回的 `10001`，与"Key 未生效/被封/未实名认证"的报错**完全一样**，
  于是白排查了数字签名、实名认证、平台类型、Referer、同步延迟、官方 MCP 网关……
- **正确姿势三步**：① 放大截图逐字符核对；② 断言长度 = 32 位十六进制；③ `curl "https://restapi.amap.com/v3/ip?key=<K>"` 看 `status:1`。
- ⚠️ 反向干扰项：JS Key 调 REST 返回 `10009 USERKEY_PLAT_NOMATCH` **不代表 Key 坏了**（只是平台类型不匹配）。
- ⚠️ `print_config()`/`validate_config()` 判 Key **只看是否非空**，占位符也会显示"已配置" ⇒ 不能用启动日志判断 Key 真假。

### 坑 6 · 工具名两套规则（见 4.1）
`MCPTool.run()` 传带前缀名会 `Unknown tool`；Agent 提示词必须用带前缀名。两者都对，别互相"纠正"。

### 坑 7 · 前端地图整块出不来 `INVALID_USER_SCODE(10008)`
- 高德 JS API Key 若配了「安全密钥」，必须在 `AMapLoader.load()` **之前**声明
  `window._AMapSecurityConfig = { securityJsCode }`，否则报 10008，地图完全白屏。
- 上游 `Result.vue:initMap()` 只传了 `key`。**已本地修复**（前置声明 + 新增 `VITE_AMAP_SECURITY_JS_CODE`）。

### 坑 8 · `Location` 字段是 `longitude`/`latitude`，**不是** `lng`/`lat`
调试/写验收脚本时读错字段会误判"坐标丢失"。`schemas.py:54` 定义的字段名就是全称。

### 坑 9 · `/api/map/*`、`/api/poi/search` 恒返空（不是你的配置问题）
`amap_service.search_poi()` / `get_weather()` / `plan_route()` / `geocode()` 内部都是
`print(...)` 之后 `# TODO: 解析实际数据` + `return []` / `{}`。**上游没写完**。
- 不影响主流程：页面规划走的是 `/api/trip/plan`（Agent + MCP 链路）。
- 想看"正确解析"的样板，参考 `get_poi_detail()`（它是唯一真的解析了 JSON 的方法）。

### 坑 10 · Unsplash 留空 = 401 刷屏 + 占位图（功能不受影响）
- 链路：`GET /api/poi/photo` → `unsplash_service.get_photo_url()` → `api.unsplash.com`（**只用 access_key**）。
- 留空时：后端 401 → 捕获异常 `return []` → 接口仍 `200 {"photo_url": null}` →
  前端 `getAttractionImage()` 回落到**渐变色 SVG 占位图**（5 套配色轮换，印着景点名）。
- 代价只是控制台每个景点打两行 `❌ Unsplash搜索失败: 401`（`poi.py` 会先搜 `"{name} China landmark"` 再搜 `"{name}"`）与加载变慢。
- **结论：留空即可。** 想配就去 https://unsplash.com/developers 免费拿 Access Key，Secret Key 不用填。

### 坑 11 · `config.py:14` 找 `HelloAgents/.env` 是死路径
`Path(__file__).parent.parent.parent.parent / "HelloAgents" / ".env"` 在本布局下必然不存在。
**无害**：前面已无条件 `load_dotenv()`（找 cwd 的 `.env`），且该分支 `override=False`。

### 坑 12 · fallback 会返回**编造数据**，验收必须看日志
`_create_fallback_plan()` 生成 `"{城市}景点1/2"`、`description="这是XX的著名景点"`，坐标是
`116.4 + i*0.01` 这类占位值。**接口仍返回 `success: true`**，前端照常渲染。
→ 验收时**必须回看后端日志**有没有 `⚠️ 解析响应失败` / `❌ 生成旅行计划失败` / `Request timed out`。

### 坑 13 · `TripRequest` 是 6 个必填字段
`city / start_date / end_date / travel_days / transportation / accommodation`，
`preferences` 是 `List[str]`（不是 `days`/`budget` 这种）。

### 坑 14 · `MCPTool.run` 的参数形状
是 `{"action": "call_tool", "tool_name": ..., "arguments": {...}}`，**不是** `{"name": ...}`。

## 九、结论一句话

**这一章的价值不在"又一堆脚本"，而在把前 8 章学的东西（Agent 角色设计、MCP 工具集成、结构化输出、Pydantic 契约）
拼成一个能跑的产品**；而它最大的教学点，恰恰是那些**静默失败**——0 个工具、超时 fallback、假 Key——
学会"看日志、看注册表、做最小对照测试"，比跑通本身更重要。
