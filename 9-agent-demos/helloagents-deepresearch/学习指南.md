## 一、这一章和前面各章最大的不同：它不再是"脚本"，而是一个完整应用

第 1–12 章基本是"一个 `.py` 演示一个知识点"。**本章是一个前后端分离的可运行产品**：FastAPI + SSE 后端、Vue3 + Vite 前端、四个服务类、三个专职 Agent、两个工具。所以学习重心从"看懂某个 API"变成"看懂一次请求怎么在系统里流动"。

**一句话抓主线**：`用户输入主题` → `规划 Agent 拆成 3~5 个 TODO` → `每个 TODO 并行"搜索→总结→写笔记"` → `报告 Agent 汇总成结构化报告` → `SSE 实时推给前端`。

### 读代码前先建立两张地图

**地图 A：一次请求的链路（后端）**

| 步骤 | 代码位置 | 产出 |
|---|---|---|
| 1. 收请求 | `main.py` → `/research/stream` | 建 `DeepResearchAgent` |
| 2. 拆任务 | `agent.py::run_stream` → `services/planner.py` | `TodoItem` 列表（3~5 个） |
| 3. 并发执行 | `agent.py::worker`（每任务一线程）→ `_execute_task` | 每任务：搜索结果 + 总结 + 笔记 |
| 4. 搜索 | `services/search.py::dispatch_search` | 结构化 results（title/url/snippet） |
| 5. 总结 | `services/summarizer.py` | Markdown 任务总结 |
| 6. 报告 | `services/reporter.py` | 五段式最终报告 |
| 7. 落盘 | `agent.py::_persist_final_report` | `notes/<note_id>.md` |

## 五、三个上游 bug 的定位与修复（本章教学价值最高的部分）

这三个 bug 都不是"改个参数"，而是**典型的编排层缺陷**，且修复前后现象极具迷惑性。强烈建议：先按原样跑一次看错误现象，再对照修复。

### bug 1 · 生成器只调用不迭代 → 非流式接口静默"假成功"（最隐蔽）

**位置**：`backend/src/agent.py::run()`

```python
# 上游（错）：_execute_task 是生成器函数，只"调用"而不迭代，函数体一行都不执行
for task in state.todo_items:
    self._execute_task(state, task, emit_stream=False)      # ← 白执行

# 本地修复：显式迭代消费生成器
for task in state.todo_items:
    for _ in self._execute_task(state, task, emit_stream=False):
        pass
```

**现象**：`POST /research` 返回 **HTTP 200 + 一份看起来挺像样的报告**，但日志里没有一次搜索、所有任务停在 `pending`、报告内容空泛。这正是生成器惰性求值的经典陷阱——**没有异常、没有报错、只有一份假成果**。

**为什么流式接口反而没问题**：`run_stream` 里是 `for event in self._execute_task(...)`，天然在迭代。

### bug 2 · planner JSON 被 `[TOOL_CALL:...]` 花括号污染 → 随机只剩 1 个任务

**位置**：`backend/src/services/planner.py::_extract_json_payload`

上游实现取"第一个 `{` 到最后一个 `}`"再 `json.loads`。但规划 Agent 的输出里常常**先有一段 `[TOOL_CALL:note:{"action":"create",...}]` 工具调用**，它的花括号和后面的任务 JSON 被你"一刀切"连成一整片：

```
[TOOL_CALL:note:{"action":"create",...}]  {"tasks":[...]}  ← 切片后变成 {...}{...}，json.loads 必然失败
```

解析失败后代码静默回退成"单任务兜底"（`create_fallback_task`），表现为**同一个主题这次 5 个任务、下次只剩 1 个**。

**修复**：改用 `json.JSONDecoder().raw_decode()` 从每个 `{` / `[` 位置逐个尝试解析，收集全部可解析载荷，再按"含 `tasks` 的对象 → 元素为对象的数组 → 任意可解析载荷"三级优先返回。见 `_extract_json_payload` 本地版。

### bug 3 · 报告 Agent 有工具能力 → 正文丢失，只剩一句交付摘要

**位置**：`agent.py::_create_tool_aware_agent` + `services/reporter.py` + `prompts.py`

上游提示词要求报告 Agent"**先读笔记 → 写正文 → 再调 note 工具保存结论**"。但 `SimpleAgent.run()` 只返回**最后一条不含工具调用的消息**。模型的实际行为顺序常常是：先吐完整正文 → 再发 `[TOOL_CALL:note:...]` 保存 → 最后补一句"报告已生成"作结。于是 `run()` 返回的就是那句**交付摘要（889 字符）**，正文被丢进历史消息里。

**修复（三处联动）**：

1. `_create_tool_aware_agent(..., use_tools=False)` → 报告 Agent 不传 registry，`enable_tool_calling=False`，**模型根本没有工具可调**；
2. `reporter.py` 把各任务总结**内联**进提示词，并明确要求"回复即最终报告、禁止 `[TOOL_CALL:...]`、禁止只回复'已完成'"；
3. 报告落盘改由 `agent.py::_persist_final_report()` 在**代码侧**完成（`note_tool.run({"action": "update"/"create", ...})`），不再依赖模型自觉。

**效果**：流式报告从 **889 字符 → 8751 字符**。

> 顺带一提：`STRIP_THINKING_TOKENS` 不是 bug 3 的原因。M3 的 `<think>` 块会被剥离，正文丢失是"模型行为不确定"造成的，剥不剥都会丢。别把两件事混在一起排查。

### 附带修复 · 后端根本没有 `load_dotenv()`

上游整个 `backend/` 没有一处加载 `.env`，`LLM_API_KEY` / `SEARCH_API` / `TAVILY_API_KEY` 全部读不到。
**关键点：必须放在 `config.py` 的模块顶层**，不能在 `Configuration.from_env()` 里加载——因为 `services/search.py` 在 **import 阶段**就执行了 `_GLOBAL_SEARCH_TOOL = SearchTool(backend="hybrid")` 并读取 `TAVILY_API_KEY`，等 `from_env()` 时已经晚了。

## 六、已知坑清单（实测踩过的，排错先查这里）

1. **停止后端要连 worker 一起杀**。`main.py` 用 `uvicorn.run(reload=True)`，会 fork 出 multiprocessing worker 并继承监听套接字。只杀父进程后 `netstat -ano | findstr :8000` 仍显示 LISTENING（PID 指向一个"已不存在"的进程，`taskkill` 会报"没有找到进程"）——真正的占用者是那个孤儿 worker。本次就踩了这个坑，最后靠 `Get-CimInstance Win32_Process -Filter "ParentProcessId=<旧PID>"` 找到并结束它。**别再 `export PATH` 时顺手 `kill` 一下就以为干净了。**
2. **后端工作目录必须是 `backend/src`**。`main.py` / `agent.py` / `services/*.py` 全是平铺 import（`from config import ...`、`import models`），在 `backend/` 或仓库根下运行直接 `ModuleNotFoundError`。
3. **DuckDuckGo 在本机不可用**。`duckduckgo.com` 超时（代理未开启时 ddgs 的 bing / yahoo / mojeek / wikipedia 后端全部失败），搜索返回的是文字提示而非结果 → 任务全部 `skipped`。本机改用 `SEARCH_API=tavily` + 复用第 5 章的 `TAVILY_API_KEY`。
4. **`LLM_TIMEOUT` 默认 60 不够**。带"景点/总结三段上下文"后，报告撰写这一步会超过 60s → `Request timed out` → **静默降级**成一段兜底文案，前端只看到一份很短的报告。已改 `300`。（实测最终规划那一步耗时可达 33s，非流式整轮 416s。）
5. **Vite 端口与 IPv6**。`vite.config.ts` 写死 `5174`，被占用会自动 +1（本次因 5174 被占实际跑在 5175）；Vite 默认绑 `::1`，**访问用 `http://localhost:5174`，不要用 `127.0.0.1:5174`**（IPv6/IPv4 不匹配会连不上）。
6. **`notes/` 是运行产物**。`ENABLE_NOTES=True` 时每次研究都会在 `backend/src/notes/`（`NOTES_WORKSPACE=./notes`，相对 cwd）新增 md 文件，重启研究不会自动清理。已在根 `.gitignore` 排除，**不要提交**。
